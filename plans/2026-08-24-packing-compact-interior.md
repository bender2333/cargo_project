# 计划：块引擎选位改为成对 (空区, 块)，内部紧凑、空隙留外

来源：2026-08-24 缝隙诊断 + 可旋转算法调研。决策见 `decision.md` 同日条目。用户已确认：混朝向允许；高度不够必须能转；主空间大时统一朝向只是偏好。

本轮 **补齐 7 月块引擎缺的 K3/K4**，不换算法门派。

---

## 意图

自动装箱从原点长成一块货，空隙留在门端 / 未贴满的外侧 / 顶部。不要在已装货中间留沿柜长的侧槽。

旋转继续走组块：6 个正交朝向都生成；空区高度不够的朝向自然进不去。不把「同货同朝向」做成硬约束。

## 边界（不改什么）

- 不改 `canPlace`、支撑比 0.5、`groundOnly`、堆高层数、重量门。
- 不改 `PackingResult` 字段、分层、标签统计的计算权威。
- 不把引擎换成墙构建 / GA / RL。
- 不从 `generateBlockCandidates` 拿掉侧立朝向。
- 不加「同一 SKU 朝向种类必须 = 1」的测试。
- 不为过测试削弱既有几何断言或越南 20GP 包络/地面空格门槛。

## 根因（file:line）

- `emsFitsForBlock`（`src/lib/packing.ts:907-917`）：每个块只按浪费最小选一个 EMS 原点。
- `selectBlockPlacement`（`:1227-1231`）：第一个可接受 fit 就 `break`。效果是最大块塞进最小洞。
- `compareBlockChoices` quantity（`:855-864`）：件数优先，waste 最后 → 窄高块打败铺满柜宽的块。
- 残件填缝（`:1264-1308`）：丢掉 EMS，改用极值点，侧槽经常看不见。
- 树搜索从未落地（`plans/2026-07-07-block-building-engine.md` 子任务 4）。

## 模块划分

只动装箱引擎，逻辑放可测纯函数，不要写进 UI。

1. **`src/lib/packing.ts`（主）**  
   选位从「遍历块 → 该块的最小浪费 EMS」改为对合法 `(ems, block, point)` 打分，取最优一对。quantity / volume 仍用各自主目标（件数 / 体积），但在接近时比较：接触已占面、是否铺满该 EMS 的宽或长、放完后剩余长方体是否碎、是否往低 x/y/z 长。  
   主空区（仍大、贴已装货）可给「该 SKU 已用直立朝向」温和加成；EMS 已经矮或窄则加成为 0。侧立块只要尺寸能进该 EMS 就必须能赢。

2. **残件阶段**  
   块循环结束后的单件 fallback 继续用当前 `emsList` 的角，而不是只用 `extremePoints`。矮 EMS 允许目录里高度能进去的朝向。

3. **lookahead（最小）**  
   对当前最优的少数几对候选，模拟 `splitEMS` 一次，惩罚「切开后出现谁也塞不进的窄条」。深度 1，宽度先小（例如 3～5）。超时或超上限则退回只评当前步。不要上完整 PCTRS。

4. **测试模块**  
   新的意图测试放 `src/lib/packing.compactness.test.ts`（或同目录等价名）。构造数据用固定种子，不要用坐标黄金当主断言。

不新建空区表示；继续用 `emsSpace.ts`。

## 验证标准

### 单测（编码意图）

1. **侧槽回归（s7 形态）**  
   输入：20GP；SKU A 400×300×400 足够铺一层但铺不满柜宽；SKU B 另一种脚印、件数足够走到 A 的 +x。quantity 模式。  
   期望：地面俯视不得出现「低 x 有货、中间空、高 x 又有货且 y 比 A 更宽」的沿柜长槽。空隙应连到门端或侧壁外沿。INTERNAL_notch = 0。

2. **外部 L 仍合法**  
   两种 SKU、总量远小于柜容积。期望：允许门端+侧边的 L 形剩余；不要为了填满而把货拽到远角另起一坨。

3. **高度受限必须仍能装**  
   柜高或剩余 EMS 高 < 原箱高，侧立后能进去。期望：该件/该块被放置，不得因朝向偏好未放置。禁止断言「朝向种类 = 1」。

4. **几何**  
   无重叠、不越界、支撑比 ≥ 0.5（走现有 invariant）。

5. **越南 20GP**  
   包络填充仍 > 88%，地面空格 < 8%，不得回退。

6. **越南 40HQ**  
   INTERNAL_notch 低于现 38；util 不低于现 77.9%；几何仍绿。

## 执行顺序与提交

1. 写侧槽 + 高度受限 RED 单测（先失败）。  
2. 成对选择 (空区, 块) + 剩余质量分，让侧槽测试绿。  
3. 残件改走 EMS。  
4. 1 步 lookahead 收窄条。  
5. 跑越南夹具与随机种子；fixture 坐标若变，先报 diff，不擅自弱化断言。  
6. CHANGELOG、release note、按 CLAUDE.md 部署并记远程回归。

每步独立 commit。提交信息例如：`test(packing): encode interior-gap compactness`、`fix(packing): select space-block pairs for compact remainder`。

## 风险

- quantity 件数优先与「铺满柜宽」冲突：件数明显更多时仍应允许多装，但不要用窄条换几件。接近时以紧凑为准。拿不准写入 `decision.md`。
- lookahead 可能让 864 件变慢。上限：越南 20GP quantity < 5s（现约 150ms 量级，允许变慢但须可交互）。超了减宽度，不要默默关掉。
- 既有 packing 硬坐标测试可能大面积变。先列 diff，架构师/用户裁决后再改断言。
