# Excel 导入与模板配置行为设计

- 日期：2026-08-19
- 状态：设计已确认，待实现前审阅
- 范围：工作簿解析后的字段映射、模板配置、预览、确认导入、相关测试行为

## 1. 背景与问题

当前导入功能已经具备 Worker 解析、字段自动映射、模板持久化、单位转换和真实业务 Excel 流程，但业务规则分散在 `CargoImportDialog`、`ImportMappingForm`、`importCargo.ts`、模板 API 和服务端路由中，形成以下风险：

- 同一源列可以被绑定到多个目标字段，产生看似成功但尺寸错误的货物。
- 模板保存只检查名称，可能保存没有有效尺寸或重量来源的不可用模板。
- 组合尺寸模式借用三个独立尺寸单位中的第一个，无法明确表达组合列的厘米单位。
- 矩阵行经过切片后丢失原始 Excel 行号，错误提示无法定位源文件。
- `mergeRows: by-label` 可以被保存，但解析器实际始终按 `none` 执行。
- 模板样例文件测试仍查找已经不存在的 `datalist`，无法保护当前真实 DOM 行为。

本设计不改变 Vite + React + TypeScript、原生 Worker、`CargoItem[]` 和现有工作台结构；只建立导入分析的单一业务契约。

## 2. 已确认的业务原则

1. 所有文件先解析为待确认预览；自动映射永远不等于自动导入。
2. 任何错误行都阻止整批确认。不得部分导入有效行，也不得覆盖当前货物。
3. 警告可以确认，但确认前必须显示原始值、有效值和警告原因。
4. 取消、关闭、解析失败、模板加载失败都不得改变当前货物数据。
5. 标签是标准货物数据的一部分；源标签存在时必须保留，不能在渲染层重新生成。
6. 模板是可复用配置，不是另一套解析器。
7. 解析、校验、单位换算和统计属于纯业务模块；React 只负责编辑配置和呈现结果。
8. 不通过修改真实夹具、放宽断言、跳过测试或把错误降级为警告来获得绿色结果。

## 3. 推荐模块边界

### 3.1 数据流

```text
Workbook Worker
  -> 原始单元格、表头、真实 Excel 行号
  -> Import Analyzer（唯一业务入口）
  -> 预览、统计、错误、警告、标准 CargoItem[]
  -> CargoImportDialog 展示并等待确认
  -> 用户确认后一次性提交 CargoItem[]
```

Worker 只负责安全解析和展开边界，不负责字段映射或业务默认值。

### 3.2 Import Analyzer 接口

实现阶段应提供一个稳定的纯函数接口，概念形状如下：

```ts
type ImportAnalysis = {
  status: 'ready' | 'blocked'
  items: CargoItem[]
  rows: ImportPreviewRow[]
  issues: ImportIssue[]
  summary: {
    sourceRows: number
    validRows: number
    warningRows: number
    errorRows: number
    skippedRows: number
    convertedRows: number
  }
}

analyzeImport(workbook: ImportWorkbook, config: ImportTemplateConfig): ImportAnalysis
```

接口必须保留：

- 每行的 1-based Excel 源行号；
- 原始单元格值；
- 映射后值和最终毫米值；
- 结构错误、文件兼容性错误、行错误、警告和跳过原因；
- 每个可导入数据行生成一个标准货物项；批量数量仍由该 `CargoItem.quantity` 表示。

`ImportTemplatePayload` 只作为 API 传输适配层。模板管理页和导入弹窗共用同一个配置校验与分析模块，不能各自复制规则。

## 4. 模板配置合同

### 4.1 结构有效性与文件兼容性分离

模板有两个独立状态：

- **结构有效**：模板本身具备可执行的字段、维度、单位和默认值配置。
- **当前文件兼容**：当前工作簿包含模板引用的源列。

结构无效时禁止保存和确认。结构有效但当前文件缺列时，模板管理页仍可保存为可复用模板；导入弹窗必须标出缺列并保持 `blocked`。没有样例文件时只做结构校验，不臆测具体列。

### 4.2 行范围

- `headerRow` 和 `startRow` 使用真实 Excel 的 1-based 行号。
- `headerRow >= 1`。
- `startRow > headerRow`。
- 转换对象行、过滤空行或跳过标题行时不得重置行号。
- 所有预览和 issue 使用源文件行号。

### 4.3 字段要求和默认值

| 字段 | 行为 |
| --- | --- |
| 长、宽、高 | separate 模式分别映射；combined 模式必须有组合尺寸列 |
| 重量 | 必须映射重量列，或提供正数模板默认重量 |
| 数量 | 未映射或空白时由 analyzer 显式使用 1，并产生警告；非数值或非正整数是错误 |
| 标签 | 有源值则保留；无映射时生成确定性标签并产生警告 |
| 名称 | 有源值则保留；无映射时使用确定性 `Cargo N` 并产生警告 |
| 颜色 | 可映射或使用模板/系统颜色；非法颜色产生警告并使用确定性回退 |
| 旋转、堆叠、最大层数、必须落地 | 可映射或使用模板默认值 |

默认值只填充空白源单元格，不覆盖非空源值。

已映射重量列的空白或非法值始终是 `invalid-weight`；模板默认重量不能掩盖已经明确映射但损坏的源列。未映射重量列只有在用户明确配置正数默认重量时才可通过。没有模板时不注入隐含重量。

源标签和模板默认标签必须去除首尾空格与控制字符，并限制为最多 80 个字符；超过限制是明确的行错误，不能静默截断或丢失 SKU 内容。模板 API 与分析器使用同一上限。

### 4.4 映射唯一性

同一源列不能映射到两个不同目标字段。例如：

```text
length -> W
width  -> W
```

必须产生配置错误，列出冲突字段，确认按钮禁用。combined 模式的组合尺寸列是唯一尺寸来源，不与隐藏的 length/width/height 控件重复计数。

### 4.5 尺寸模式和单位

- separate 模式：长、宽、高各自拥有 `auto | mm | cm`。
- combined 模式：使用明确的 `combinedUnit: auto | mm | cm`，不再借用三个独立单位中的第一个。
- `auto` 先读取表头单位；表头没有单位时按毫米处理，并显示单位假设警告。
- 组合值必须恰好包含三个正数，支持 `x`、`*`、`×` 和空格分隔。
- 单位变化后同时展示原始值和换算后的毫米值。
- 不把含义不明确的逗号格式静默解释为另一种分隔方式。

### 4.6 未实现配置

`mergeRows: by-label` 当前没有实际解析语义。为避免保存一个看似有效但始终失效的选项：

- 从活动模板领域模型、编辑界面和新传输合同中移除 `mergeRows`。
- 本轮不定义按标签合并时的数量、重量、尺寸和冲突规则。
- 若未来需要按标签合并，必须另立需求并先定义完整业务语义。

## 5. 解析规则与 issue 分类

### 5.1 行状态

每行只有一种最终状态：`valid`、`warning`、`error` 或 `skipped`。

- `valid`：无警告、无错误。
- `warning`：可确认，但必须展示原因和最终采用值。
- `error`：本行不可导入；任何 error 都使整批 `blocked`。
- `skipped`：空行、标题行、汇总行等非货物行；保留源行号和跳过原因。

### 5.2 错误与警告

配置错误：

- 必填尺寸来源缺失；
- 重复映射；
- 非法维度顺序或单位；
- `startRow <= headerRow`；
- 组合模式缺失组合列。

文件兼容性错误：

- 模板引用的源列不在当前表头；
- 表头行不存在或没有可用列。

行错误：

- 长、宽、高不能解析为正数；
- 重量缺失、非有限或不大于零；
- 数量列存在但值不是正整数；
- 布尔规则包含无法识别的值。

警告：

- 数量使用默认值 1；
- 标签或名称使用回退值；
- 自动单位采用毫米假设；
- 厘米换算；
- 颜色使用回退值。

不得用 `Number('') = 0`、静默 `floor`、未知布尔值回退或控制台日志代替 issue。

## 6. 映射弹窗行为

### 6.1 状态机

1. **解析中**：显示进度；超限、超时或不可读时不打开映射弹窗，只显示可见导入日志。
2. **待配置**：展示自动映射建议，等待用户检查。
3. **配置变更**：调用同一个 analyzer 生成新预览。
4. **阻止确认**：存在配置错误、缺列或任意行错误。
5. **可确认**：无错误，可有警告。
6. **确认提交**：只提交当前分析结果中的 `items` 一次。
7. **取消/关闭**：释放待处理状态，不写入货物或输入 revision。

### 6.2 预览

前 5–10 行展示：

- 源 Excel 行号；
- 原始标签、名称、尺寸、重量、数量；
- 映射后的字段；
- 换算后的毫米值；
- 实际采用的默认值或回退值；
- 行状态、字段、原始值和修复建议。

顶部统计固定展示：源数据行数、有效行数、错误行数、警告行数、跳过行数和厘米换算行数。

确认按钮必须同时满足：

```text
结构配置有效
当前文件无缺列
分析结果没有 error 行
至少存在一条有效货物
```

错误存在时，按钮 disabled 且显示阻止原因；警告存在但没有错误时，按钮可用并保留警告。

## 7. 模板管理行为

### 保存与编辑

- 新建和编辑使用同一结构校验器。
- 只有名称非空不再足够；没有有效尺寸来源或重量来源时禁止保存。
- 服务端拒绝非法语义；只做无歧义的空白清理和类型规范化，不把错误静默改成默认值。
- 保存失败显示页面内 `role="alert"` 错误。
- 重复名称显示明确冲突，不显示成功通知。

### 选择和生命周期

- 选择模板只预填配置，不自动确认或覆盖当前货物。
- 当前文件缺列时保留模板选择并标红缺列。
- 模板加载失败不被视为模板删除。
- 删除成功后才清理引用；重命名同步权威名称，但不覆盖用户已经输入的“另存为”名称。

### 样例文件

样例文件只提供模板管理页的列选项，不触发导入。多个样例请求采用 latest-wins：较早请求完成后不能覆盖较晚请求；失败时清空旧样例并显示可见错误。测试断言当前实际使用的 `select` 选项，不查找旧 `datalist`。

## 8. 测试合同

### 8.1 纯业务测试

必须覆盖：

1. 重复映射被拒绝；
2. 仅名称或没有有效尺寸/重量来源的模板被拒绝；
3. separate/combined 两种必填规则；
4. combined cm：`53×30.5×31 -> 530×305×310 mm`；
5. `headerRow=2/startRow=3` 时 issue 使用真实第 3 行；
6. 有效行与错误行并存时整批 `blocked`；
7. 映射重量为空不被默认重量掩盖；
8. 未映射重量只有明确默认值才通过；
9. 非整数数量、非法布尔值、非法尺寸和非法重量不静默回退；
10. 中文、长文本和特殊 SKU 标签不丢失；
11. 活动模板合同不再包含 `mergeRows`。

### 8.2 React 测试

必须覆盖：

- 重复映射时确认 disabled 且 `onConfirm` 不调用；
- 缺列时弹窗保持打开、当前货物不变；
- 只有警告时可以确认；
- 取消不提交；
- 模板保存需要结构有效；
- 样例文件乱序完成时只保留最新列选项；
- 样例失败清除旧成功状态并显示错误；
- 测试选择器与当前 `select` DOM 一致。

### 8.3 E2E

继续使用真实夹具验证：

- 俄罗斯工作簿 31 个有效货物、标签保留、指定柜型 31/31；
- 越南工作簿标题行、组合尺寸、箱数优先、重量映射和汇总行；
- 中文厘米工作簿的原始/换算预览和警告；
- 重复映射、缺列、错误行的整批阻止与数据不变；
- 模板创建、复用、重命名、删除和当前文件缺列；
- CSV 与 XLSX 共用同一分析路径。

## 9. 不在本轮范围

- AI 自动字段决策；自动映射仅提供可审查建议。
- 部分导入有效行。
- 全局状态库。
- 将解析逻辑搬入 React。
- 未定义语义的按标签合并行。
- 修改真实 Excel 夹具或放宽既有装箱验收断言。

## 10. 采用方案

比较过三种方案：

- 在现有文件上最小修补：改动小，但规则仍会在多个入口漂移。
- 建立统一 `Import Analyzer` 深模块：保留现有 Worker、React 和 API，集中校验、转换、预览和 issue 合同。
- 将预览移到服务端：一致性更强，但引入上传生命周期和网络复杂度。

采用第二种方案。它在不重做现有架构的前提下，最大化规则的局部性和测试复用。
